# Crate Boundary Inventory

## Purpose

This file explains the dependency architecture. The machine-readable source is `project/boundaries.json`; `reports/boundary-inventory.md` is regenerated by the inventory command.

## Boundary rules

1. **Domain:** platform-independent IDs and value types only; no registry, filesystem runtime or OS APIs.
2. **Foundation:** shared diagnostics/config/protocol contracts; no platform implementation dependencies.
3. **OCI:** image-spec parsing and registry protocol; no process execution.
4. **Content:** fetch, digest and verified content cache; no image policy or native runtime decisions.
5. **Filesystem:** layer semantics, safe unpacking and logical RootFS; no platform VM APIs.
6. **Contracts:** NIR and shared schemas; no compiler orchestration or platform SDKs.
7. **Analysis:** static image inspection and compatibility; no execution side effects.
8. **Compiler:** orchestration only; must not depend on concrete platform backend crates.
9. **Artifact/trust:** packaging, SBOM, signatures and provenance; no host execution.
10. **Runtime/platform:** lifecycle and capability interfaces; native bridges remain inside platform-specific crates.
11. **Apps:** CLI/launcher/daemon composition layer; never imported by core crates.

## Dependency enforcement

`scripts/i2n.py inventory` reads Cargo workspace membership and each crate manifest. It reports:

- missing or untracked workspace members;
- crate metadata not present in boundary inventory;
- local path dependencies outside the workspace;
- workspace dependency edges whose target group is not permitted;
- external crate dependencies not explicitly allowlisted by the owning boundary;
- generated inventory drift when `--check` is used.

The boundary rules are intentionally conservative at the beginning. A legitimate new edge requires updating `project/boundaries.json`, explaining why in an ADR, and adding an architecture test when the boundary is important.

## Native bridge rule

Swift/Objective-C, Apple framework calls, Win32/WSL/HCS calls and direct Linux host syscalls must remain in `platform/<os>/` or the matching `i2n-platform-<os>` crate. Do not expose native handles in NIR or shared domain types.
